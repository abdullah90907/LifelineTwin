# Geographic engine method

Inputs are a directed NetworkX MultiDiGraph with nonnegative `length` weights in metres, origin-node records, and facility-node records. The pure engine has no Zetaris or Meterless dependency. Future adapters can supply these inputs without changing the routing algorithm.

OSMnx downloads a driving network for west/south/east/north `(8.650, 49.395, 8.705, 49.435)`, central Heidelberg, Germany, approximately 4 by 4.5 km. All components are retained so unreachable origins are visible. OpenStreetMap hospital features use `amenity=hospital`; no claim is made about emergency services, operational status, or capacity. OSM contributors supply the data under ODbL: https://www.openstreetmap.org/copyright.

Nine representative target locations form a 3 by 3 grid at 20%, 50%, and 80% of each bbox dimension. Each maps to its nearest driving-network node by great-circle distance; duplicate nodes are removed. These are geographic samples, not population-weighted demand. Hospitals use a point within their OSM geometry and the nearest road node. Snapping offsets are saved, but excluded from route distance. They are not verified entrances or legal vehicle access paths; river barriers, campuses, and hospital entrances can make geometric snapping misleading.

The reversed directed graph supports a multi-source Dijkstra search from all facility nodes. Reversing the returned path produces an origin-to-hospital driving route; direction and parallel-edge minimum lengths are preserved. Missing paths are reported as unreachable, never as zero. No speeds are inferred, and no travel times, congestion, turn restrictions, ambulance exemptions, or route safety are modeled. A fixed bounding box excludes hospitals and detours outside the study area and can cause artificial disconnections.

Three hypothetical closure segments are selected deterministically from the most frequently used baseline-route links, with node IDs breaking ties; links sharing an endpoint with an already selected closure are skipped to avoid immediately adjacent closures. This deliberately stresses important routes, not a forecast or random risk sample. A segment is the simplified link between two junction nodes; all parallel edges in both directions between those endpoints are removed. It is not an entire named street. Separate carriageways with different endpoints are not automatically closed. The JSON output records exact endpoints and labels.

All three segments close together. Each restoration starts from the original graph with the other two still closed, avoiding cumulative reopening. Rank by (1) number of previously unreachable origins reconnected, then (2) total distance reduction across origins reachable in the fully disrupted graph. Reconnected origins do not receive an arbitrary infinite-distance penalty. Equal scores tie, with closure ID used only for display order. Reopening cost, population, capacity, and restoration time are not included; this is an accessibility comparison, not an operational recommendation.

Acquisition is explicit (`download`). GraphML, raw facility GeoJSON, origin/facility node mappings, and SHA-256 hashes are cached. OSMnx also caches the HTTP responses. A completed cache is reused and checked without downloading again. `analyze` only loads verified local files. Raw downloads can occur at slightly different times; the completion timestamp is not an atomic OSM snapshot. Preserve the cached files to reproduce this run. Use a different cache directory for a deliberate refresh rather than overwriting the original snapshot.

References inspected: [OSMnx API](https://osmnx.readthedocs.io/en/stable/user-reference.html), [NetworkX multi-source Dijkstra](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.shortest_paths.weighted.multi_source_dijkstra.html).
